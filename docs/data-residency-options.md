# 「東京のみ」が必須だった場合の選択肢

現状、文案生成は Claude Haiku 5.5 の日本向け推論プロファイル `jp.anthropic.claude-haiku-5-5` を使う。
これは**東京（ap-northeast-1）と大阪（ap-northeast-3）の間**で処理されるため、「東京リージョン内だけ」ではない。
「日本国内」で良いなら現状のまま。**東京単独が必須**なら、次のどれかを選ぶ。

| 案 | 何を変えるか | 利点 | 欠点 |
|---|---|---|---|
| A. 文案生成をやめる | `POST /copy` を削除。テンプレート差し込みだけにする | データが東京から出ない。コスト0 | 文面のバリエーションが落ちる。実装は `llm.py` を消すだけ |
| B. 東京提供の他モデルに替える | `-c modelId=` を東京単独提供のモデルに変更 | 変更が小さい | 文章品質・日本語品質はモデル次第。事前に品質評価が必要 |
| C. 自社GPU等でホストする | LLM を VPC 内に置き、Lambda から VPC 経由で呼ぶ | 完全に東京完結 | 運用負荷・コストが大きい。5.5 相当は現実的でない |
| D. 文案は自社オンプレで生成 | AWS には文案を置かず、自社システムが生成・保持 | データ主権を保てる | `POST /copy` の役割がなくなる。カルテに文案を保存しない設計に変える |

## 判断に必要な事実

- **カルテ、行動履歴、レコメンドはすべて東京**（S3 / DynamoDB / KMS / Personalize のデータセット）。
- 外に出るのは**文案生成のプロンプトだけ**。プロンプトには氏名・住所・電話・メールを含めない
  （`{{customer_name}}` のプレースホルダ、興味カテゴリ、購入回数、商品名のみ）。
- したがって「個人情報を外に出さない」は現状でも満たしている。争点は「**東京リージョン外に一切出さない**」かどうか。

## 実装済みの切り替え

- `modelId` は CDK のコンテキストで差し替え可能。IAM もそのモデルにだけ許可している。
- 代替モデルへの**自動フォールバックはしない**（黙って別モデル・別リージョンに流れないようにするため）。
