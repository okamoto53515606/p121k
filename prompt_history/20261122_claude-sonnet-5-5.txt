**妙案は「PIIを持たないカルテ」です。**
- **仮名ID:** 会員IDは自社側で HMAC により仮名化してから S3 に置きます。氏名、メール、住所、電話は AWS に入れません。
- **文案の差し込み:** Bedrock が作る文案は `{{customer_name}}` のようなプレースホルダ付きにします。実名の差し込みは自社サーバ側で行います。
- **アクセス制御:** API Gateway は IAM 認証のみにして、ブラウザから直接呼ぶ経路は作りません。
- **削除:** 顧客ごとのデータキーを破棄する暗号消去を使います。
- **接触NG判定:** 未解決クレームや返品の多さなどをルールで決めます。LLM は問い合わせの分類と要約だけに使います。

**アーキテクチャ。** CDK 1スタックで、S3 の inbound に置いたファイルを Step Functions が取り込みます。その後、DynamoDB のカルテ、Personalize、Bedrock の順に処理します。

**オープンデータ。** 主データには Amazon Reviews 2023 を推奨します。アイテムマスタ、会員、購入の代わりになるレビューが、ひとつの ID 体系で揃うためです。クレームの代わりには Olist や、低評価レビューを変換したものを使えます。問い合わせ文は Haiku による日本語合成が現実的です。

**確認できたこと**
- Personalize の User-Personalization-v2 は、最低 1,000 件の行動データで使えます。
- Personalize と Bedrock は東京リージョンで使えます。

**未確認で、デプロイ前に要確認のこと**
- **Claude Haiku 5.5:** 東京での提供有無は確認できていません。
- **推論の処理場所:** クロスリージョン推論だと、処理が東京の外に出る可能性があります。
- **Personalize の削除:** 個別レコードを削除しにくいため、除外フィルタと定期的な全件再取込で対応する想定です。

退会の追加、Haiku 5.5 の東京提供とコスト、使うデータとライセンスの確認結果を `karte-outline.md` に反映しました。

**1. 退会**
- 行動履歴の `event_type` に `withdraw` を追加しました（`item_id` は空欄、`reason` は任意）。
- 退会したら即座に接触NGにし、文案もレコメンドも出しません。
- 保持期間が過ぎたら、削除APIと同じ暗号消去を自動で実行します。保持日数は設定値にして、法務で決めます。
- 退会後のイベントは隔離します。再入会は新しい会員IDで別人として扱います。

**2. Haiku 5.5 の東京提供とコスト**
- **提供:** 東京単独で推論する方式はありません。使えるのは、東京と大阪の間で処理される日本向けの推論プロファイル（`jp.anthropic.claude-haiku-5-5`）だけです。
- **要件への影響:** 「東京リージョン完結」は、実際には「日本国内（東京・大阪）完結」になります。「東京のみ」が必須なら、この構成は成り立ちません。この要件はあなたの判断が必要です。
- **単価:** 日本向けプロファイルは、入力が100万トークンあたり$0.11、出力が$0.55です。これは価格集計サイト（第三者）の数字です。AWS公式の価格表では確認できなかったので、デプロイ前に要再確認です。
- **試算:** 10万会員に案内文を1回生成して約$55（約8,300円）です。推論モードが既定でオンのため、オフにするか低めに設定する前提です。
- **Personalize v2:** 無リクエストでもリアルタイムのCampaignは月約$390かかります。そのため、バッチ推論だけを使い、Campaignは作らない構成に変えました。

**3. データとライセンス**
- **採用:** 骨格は REES46 の行動データ（view、cart、purchase）にしました。作者が「無料で利用可、出典明記」と記載しています。ただし、これは正式なライセンス文ではないので、法務確認とREES46への確認を推奨します。
- **参考:** Bitext（CDLA-Sharing-1.0）は問い合わせの意図分類の参考にとどめ、本文は自前で合成します。
- **不採用:** Olist と Retailrocket は CC BY-NC-SA 4.0（非商用）なので外しました。Amazon Reviews 2023 はライセンスの記載が見つからず、保留のうえ不採用です。
- **合成:** 商品名・説明、like、返品、退会、日本語の問い合わせは、Haiku で作ります。

REES46 は商品名と説明を持たないため、その合成は必須です。

### 2. Haiku 5.5 を Batch にする → 賛成（ただし条件付き）
- 文案生成も問い合わせ分類も、リアルタイム性は要りません。週次バッチなら Batch で約50%安くなります。
- Bedrock の価格ページには Batch 割引の記載がありました。

- API の `POST /copy` は即時生成なので残します（任意の再生成用）。

### 3. Guardrails は不要 → 賛成
- 日本語の PII 検出は弱く、課金もあります。今も使っていません。
- PII 対策は次の3つで足ります。
  - 入力そのものを減らす（次項）。
  - 正規表現による伏字化。
  - 文案は `{{customer_name}}` のプレースホルダ固定。
- 保存前に、出力内の電話・メール形式を再スキャンする処理は足せます。

### 4. 問い合わせは分類コードだけ PUT → 強く賛成
- 全文を S3 に置くと、一番漏れてはいけないデータが一番危険な場所に集まります。KARTE の事故の教訓そのものです。
- 分類は自社側で行い、次の形式で送ります。
  - 列は `inquiry_id, member_id, received_ts, category` です。
  - `category` は `complaint / question / request / other` のコードです。
  - `other` のときだけ `note`（40字以内、個人情報なし）を付けます。
- 自社側の分類には、ルールか自社の Haiku を使います。
- 分類が不要になるので、AWS 側の問い合わせ分類 LLM が丸ごと消えます。Bedrock は文案生成だけになり、構成も軽くなります。
- 本文を万一送ってしまった場合に備え、`note` の長さ制限と伏字化は AWS 側にも残します。

### 5. 毎回 FULL 分析、退会したら即削除 → 賛成
- 後戻りになる箇所は次のとおりです。
  - **保持期間（30日）と purge の仕組みは廃止します。** `withdraw` を取り込んだ時点で、カルテ・interactions・レコメンドを即削除します。
  - **退会済みのカルテは作りません。** 現状は `withdrawn` の状態レコードと削除用の墓標（`deleted`）を持っています。
  - **墓標を残すか消すかを決める必要があります。** 完全削除にすると、退会者の古いイベントが次の FULL でまた入り込みます。
- 提案は次のとおりです。
  - 毎回 FULL 実行時に、S3 の全行動履歴を時系列で再読込します。
  - 退会イベントを持つ会員は、その会員の全履歴を捨てます。
  - これにより、DynamoDB に退会者の痕跡が残りません。
  - 墓標は不要です。「S3 に退会履歴が残る限り、FULL のたびに必ず除外される」という仕組みが代わりになります。
  - 副作用として、FULL にすれば差分取込の排他制御・冪等管理・バージョン管理が不要になります。
  - S3 を消すとカルテも消せる、という単純な設計になります。
  - 週1の FULL で、DynamoDB はその都度作り直す（または入れ替える）形になります。
- FULL の間に退会したケースだけは別途必要です。
  - `DELETE /karte/{id}` を、即時の退会・削除用としてそのまま使います。
  - S3 に退会行が入ったら、次の FULL で必ず反映されます。
- S3 の ingest 用 Lambda（15分上限）は FULL に向きません。取込を Step Functions + Glue / Athena / Fargate に置き換える可能性があります。
- 10万会員、数百万イベントなら、Lambda を分割するだけでも足ります。

## Haiku 5.5 の有効化とバッチAPIについて

### バッチAPIは使えません
- Bedrock に `jp.anthropic.claude-haiku-5-5` のバッチジョブを作成しようとすると、`Batch inference is not supported for the requested model` で拒否されました。
- これは有効化の有無に関係なく出るエラーで、Haiku 5.5 自体がバッチ非対応です。
- 同じ要領で Haiku 4.5 のジョブはバッチとして受け付けられました。
- 文案生成は即時API（`POST /copy`）のまま使います。
- 10万会員でも節約額は約$27/回なので、この結果で困ることはほとんどありません。

### 有効化の方法
- このアカウントの状態は、利用の許可はあるが、Marketplace の契約が未同意です。
- 契約条件は従量課金で、返金なしです。
- 料金は Bedrock の Marketplace オファーの料金表で確認しました。日本向けプロファイルは入力 $0.11 / 出力 $0.55 /100万トークンで、以前の数字と一致しています。
- 方法は2つあります。
  1. **コンソール**: Bedrock の Model catalog で Claude Haiku 5.5 を開き、Marketplace の契約に同意します。
  2. **CLI**: `aws bedrock create-foundation-model-agreement --model-id anthropic.claude-haiku-5-5 --offer-token <トークン>` を実行します。トークンは `aws bedrock list-foundation-model-agreement-offers --model-id anthropic.claude-haiku-5-5` で取れます。
- <profile> ユーザーは AdministratorAccess なので、権限は足りています。
- 契約への同意は料金条件への同意になるため、こちらでは実行していません。コンソールで進めるか、実行してよければ指示してください。
- 有効化後は、アプリ側の変更は不要です。`jp.anthropic.claude-haiku-5-5` が優先して使われ、失敗したときだけ Haiku 4.5 に落ちます。
- 有効化後に、`POST /karte/{id}/copy` の応答の `model` が `jp.anthropic.claude-haiku-5-5` になっていることを確認してください。
